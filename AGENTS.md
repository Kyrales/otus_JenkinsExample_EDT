# Инструкции для Codex

## Основные правила

Всегда сначала прочитай `rules/ru/INDEX.md` — это навигатор по правилам работы с проектом и MCP-сервером EDT.

Общайся с пользователем на русском языке, если он сам не попросил другой язык.

## Проектный контекст

- Проект: `otus_JenkinsExample_EDT`.
- Конфигурация: демо-приложение 1С для примера Jenkins/EDT pipeline.
- Основной EDT source set: `otusJenkinsExampleEDT`, путь `src/cf/otusJenkinsExampleEDT`.
- Расширения: `YAXUNIT` и `Колонтитулы`, пути в `src/cfe/`.
- Формат проекта: EDT.
- Платформа 1С: `8.3.27` (`v8config.json`: `8.3.27.2130`).
- Сборка и тесты описаны в `v8project.yaml`; рабочий каталог `build`.
- MCP-серверы Codex настроены в `.codex/config.toml`: `edt-mcp` и `v8-runner`.

## Работа с EDT-MCP

- Для операций с проектами EDT сначала предпочитай инструменты `edt-mcp`, если они доступны.
- После изменений в коде или метаданных проверяй состояние проекта через `get_problem_summary` или ближайший доступный инструмент валидации.
- Если правило из `rules/` ссылается на MCP-инструмент, которого нет в текущей сессии Codex, не выдумывай вызов: используй доступный аналог или явно напиши пользователю, что инструмент не опубликован сервером.

## Проверка результата

Предпочтительные проверки:

- Сводка проблем EDT: `edt-mcp.get_problem_summary`.
- Полная перевалидация при необходимости: `edt-mcp.clean_project`.
- Команды сборки и тестов проекта: через `v8-runner` согласно `v8project.yaml`.
