# Заполнение контрагента из DaData — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить ИНН и заполнение существующих реквизитов контрагента из DaData по кнопке, сохраняя ключ вне конфигурации.

**Architecture:** Серверный общий модуль `DaDataКонтрагенты` отделяет преобразования от файла и HTTPS. Форма применяет подготовленные данные к незаписанному объекту с учетом прав. YAxUnit-тесты расширения проверяют реальную логику на синтетических входах, сетевой адаптер проверяется отдельным smoke.

**Tech Stack:** 1С:Предприятие 8.5.1.1522, совместимость 8.3.27, BSL, EDT-MCP, существующее расширение YAXUNIT, HTTPS/JSON платформы.

**Spec:** `docs/superpowers/specs/2026-10-13-counterparty-dadata-design.md`

## Global Constraints

- Не изменять платформу, режим совместимости, тестовый фреймворк или схему CI ради этой функции.
- Все чтение и запись BSL выполнять только через EDT-MCP; для точечных правок использовать `expectedHash`.
- Метаданные и формы создавать/изменять через `create_metadata` и `modify_metadata`; старые названия инструментов из правил не использовать, если сервер их не публикует.
- После записи проверять измененные объекты и форму; исходные ошибки фиксировать отдельно от новых.
- Для проверок использовать `build/ib_extend`; `build/ib` не обновлять.
- Реализация по TDD: для каждого нового поведения сначала тест, наблюдаемый RED, минимальная реализация, GREEN и рефакторинг при необходимости.
- Настоящий ключ и `.env` не включать в Git, фикстуры, скриншоты и отчеты.
- Сохранить уже измененные пользователем `AGENTS.md`, `Configuration.mdo`, `v8config.json`; в `Configuration.mdo` учитывать только добавления своей задачи.

## Review Focus

- Неоднозначный ответ или чужой ИНН не должен менять ни одно поле — тесты Task 2/3.
- JSON-null, неверные типы и нулевые координаты не должны очищать значения или теряться — Task 2/3.
- Переполнение строковых полей не должно тихо обрезать данные — Task 3.
- Отсутствующий/дублирующийся регион и запреты редактирования не должны приводить к случайной ссылке или обходу прав — Task 3/4.
- Ошибки файла, HTTP и JSON не должны раскрывать ключ или частично изменять карточку — Task 1/2/3/4.

## Контракт результатов и интерфейсы

Все указанные далее методы общего модуля экспортные, серверные. Результат операции — структура `Успех` (Булево), `КодОшибки` (Строка), `Сообщение` (безопасная локализованная Строка), `Данные` (Структура, только целевые непустые поля), `Предупреждения` (Массив строк), `ИменаРегиона` (Массив строк). При ошибке `Данные` пустая; ключ в результат не включать. Чистые функции разбора не обращаются к БД, файлам или сети.

| Метод | Контракт |
|---|---|
| `НормализоватьИНН(ИНН)` | Строка → нормализованная строка; безопасное исключение для неверного формата/контрольных цифр |
| `КлючИзТекстаНастроек(Текст)` | Строка → строка токена; безопасное исключение для неверного `dadata` |
| `ПрочитатьКлюч(Путь)` | Строка абсолютного пути → токен; закрывает файл, безопасное исключение |
| `СоздатьЗапрос(ИНН, Ключ)` | валидный ИНН и токен → реальный `HTTPЗапрос` с JSON UTF-8 и заголовками из спецификации |
| `РазобратьОтвет(КодHTTP, Тело, ИНН)` | число, строка, нормализованный ИНН → структура результата; исключения парсера наружу не выходят |
| `НайтиРегион(ИменаРегиона, Кандидаты)` | Массив строк, ТаблицаЗначений `Ссылка, Наименование` → ссылка или пустая ссылка; неоднозначность возвращает пустую ссылку |
| `ПрименитьДанные(Контрагент, Результат, РазрешенныеПоля)` | незаписанный СправочникОбъект, результат, Массив имен → Массив предупреждений; не пишет объект; ошибка результата ничего не меняет |
| `ПолучитьДанные(ИНН, Путь, Транспорт = Неопределено)` | входной ИНН, абсолютный путь, необязательный серверный объект отправки → структура результата; валидация, файл, построение запроса, HTTPS, разбор ответа; безопасно преобразует исключения |
| `ОтправитьЗапрос(Запрос)` | реальный HTTPЗапрос → структура `КодHTTP` (Число), `Тело` (Строка); серверная внешняя граница, исключения ловит `ПолучитьДанные` |

Перед первым тестом каждого следующего интерфейса создать только его компилируемую заглушку, без продуктового поведения: нормализатор/reader возвращают пустую строку, построитель запроса возвращает HTTPЗапрос с пустым путем, парсер/оркестратор — результат Успех=Ложь с пустыми данными, подбор региона — пустую ссылку, применение — пустой массив предупреждений без изменений объекта. Тест должен провалиться на конкретном ожидаемом результате, а не на отсутствии метода. Для заглушки применяется наблюдаемый RED до написания тела; наличие сигнатуры само по себе не считается реализацией поведения. Для следующих ветвей уже существующего метода заглушку повторно не создавать: RED должен обнаруживать отсутствующее новое поведение.

## Список тестов, создаваемых до реализации

Это обязательный перечень будущих тестов, а не отчет о выполненных проверках. Все модульные тесты размещаются в `src/cfe/otusJenkinsExampleEDT.YAXUNIT/src/CommonModules/ОМ_DaDataКонтрагенты/Module.bsl` и регистрируются в `ИсполняемыеСценарии`. Указанные варианты одного сценария реализуются параметризацией YAxUnit.

**Порядок:** перед реализацией соответствующего поведения написать тест из этого перечня, запустить и сохранить ожидаемый RED; только затем писать продуктовую реализацию и получать GREEN. Полный перечень фиксируется заранее; исполняемые тесты добавляются последовательно по TDD-циклам, до своего поведения, а не после готовой функции. Если для компиляции нужна сигнатура, допустима только описанная выше заглушка без поведения. Метаданные проверяются тестом до их изменения.

| `НеверныеТипыНеобязательныхПолей` | вместо строки/массива/адресного узла неожиданный тип → пропуск соответствующих полей с предупреждением без исключения |
| `НулевыеКоординаты` | geo_lat/geo_lon=`0` → числовые нули присутствуют в Данные |
| `НеверныеКоординаты` | нечисловое значение или выход за диапазон → пропуск этой координаты с предупреждением; вторая корректная сохраняется |
| `ОкруглениеКоординат` | десятичная точка и больше 6 знаков → число, округленное до 6 знаков; границы ±90/±180 принимаются |
| `ГородИзПоселения` | нет city_with_type, есть settlement_with_type → название населенного пункта |
| `ДомКорпусСтроение` | house/block/building → строка из непустых частей с типами через `, `, без пустых разделителей |
| `ПервыйНепустойКонтакт` | пустая первая запись phones/emails/sites → первая последующая непустая; fallback value → source/domain |
| `КонтактБезРуководителя` | management.name отсутствует → phones[].data.contact; при наличии руководителя его имя имеет приоритет |
| `ПустойОтвет` | suggestions=[] → NOT_FOUND и пустые Данные |
| `ЧужойИНН` | подходящих записей с запрошенным ИНН нет → INVALID_RESPONSE и пустые Данные |
| `НеоднозначныйОтвет` | несколько подходящих MAIN/ИП с запрошенным ИНН → INVALID_RESPONSE; не выбирать первую |
| `СломанныйJSON` | некорректный JSON → INVALID_RESPONSE; текст парсерного исключения не выходит наружу |
| `НевернаяСтруктура` | suggestions/data отсутствуют либо имеют неверный обязательный тип → INVALID_RESPONSE |
| `ФилиалНеПодходит` | только BRANCH → не заполнять карточку; BRANCH рядом с единственной подходящей MAIN не выбирать |
| `ОшибкаДоступа` | HTTP 401/403 → ACCESS_DENIED; тело с unit-secret-marker не раскрывается |
| `ЛимитЗапросов` | HTTP 429 → RATE_LIMIT без раскрытия тела |
| `ОшибкаСервиса` | HTTP 500/503 → SERVICE_ERROR без раскрытия тела |
| `ДругойКодHTTP` | HTTP 400/404 → HTTP_ERROR без раскрытия тела |
| `СтатусНеАктивен` | LIQUIDATED → успех с предупреждением; ACTIVE/отсутствующий статус не создают такого предупреждения |

### Task 3 — метаданные, регион и применение

| Тест | Вход и ожидаемый результат |
|---|---|
| `ИННИДлиныРеквизитов` | до изменения метаданных: проверка ИНН String(12) и новых пределов строк из спецификации дает RED; после изменения → GREEN |
| `РегионЕдинственный` | одна совпадающая ссылка по region_with_type либо region с нормализацией регистра/краевых пробелов → эта ссылка |
| `РегионОтсутствует` | нет совпадений → пустая ссылка |
| `РегионНеоднозначный` | два разных совпадающих региона → пустая ссылка |
| `ДваИмениОднойСсылки` | совпадения по двум именам ведут на одну ссылку → единственная ссылка |
| `ЗаменяетПолученныеПоля` | успешный результат с разрешенными полями → полученные значения заменяют прежние |
| `СохраняетОтсутствующие` | null/пустые/отсутствующие данные → прежние значения остаются; существующий телефон не стирается |
| `НеМеняетСлужебныеПоля` | заполнение → код, группа, вид цен, факс и дополнительная информация прежние |
| `ОшибкаНеМеняетОбъект` | Успех=Ложь → все исходные реквизиты объекта прежние |
| `ДлинноеПолеПропускается` | для каждого ограниченного поля значение длиной N принимается, N+1 сохраняет прежнее значение и дает предупреждение |
| `ЗапрещенноеПолеСохраняется` | поле отсутствует в РазрешенныеПоля → прежнее значение и предупреждение; разрешенные поля заполняются |
| `РегионНеНайденСохраняется` | результата сопоставления нет → старая ссылка региона остается |
| `ПрименениеНеЗаписываетОбъект` | применение к новому объекту → его ссылка остается пустой, новой записи с уникальной тестовой меткой в БД нет |

### Task 4 — оркестрация и безопасные исключения

| Тест | Вход и ожидаемый результат |
|---|---|
| `ОркестраторУспех` | реальный временный файл с unit-token и тестовый транспорт → реальная оркестрация возвращает заполненные Данные |
| `НеЗапрашиваетСервисПриНеверномИНН` | bad + пустой путь + транспорт, бросающий исключение → INVALID_INN, не ошибка файла/транспорта |

## Единый способ запуска TDD-групп

До первого запуска проверить `get_applications(projectName="otusJenkinsExampleEDT")`, applicationId и отсутствие посторонних сеансов; старт требует реального приложения, не `launch:<name>`. Текущий найденный applicationId `867ff919-3b34-4103-9116-42bd2dd45866` перепроверить. Если база требует обновления — выполнить preview/apply `update_database` отдельно.

```json
{
  "projectName": "otusJenkinsExampleEDT",
  "applicationId": "867ff919-3b34-4103-9116-42bd2dd45866",
  "modules": ["ОМ_DaDataКонтрагенты"],
  "tests": ["ОМ_DaDataКонтрагенты.ИННЮрлица"],
  "timeout": 45,
  "updateBeforeLaunch": true,
  "externalInfobaseChanges": "cancel"
}
```

Это параметры `edt-mcp.run_yaxunit_tests`, не shell-команда. Для отдельной группы заменить `tests` конкретными методами, для всего нового модуля убрать `tests`, для полной suite убрать и `tests`, и `modules`. При Pending продолжать через `get_job_status(jobId, waitSeconds=45)`, не повторять start. GREEN: каждый ожидаемый тест выполнен, failures=0, errors=0, нет непредусмотренных skipped. RED: именно ожидаемый тест провален на контракте нового поведения, а не запуске/компиляции.
