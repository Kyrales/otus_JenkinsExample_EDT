# Заполнение контрагента по ИНН из DaData

Дата: 2026-10-13. Статус: спецификация для согласования перед реализацией.

## Согласованные требования

Добавить ИНН в справочник `Контрагенты`. В карточке пользователь вводит ИНН и нажимает «Заполнить по ИНН». Заполняются все данные DaData, для которых в справочнике есть подходящие реквизиты. Искать головную организацию или ИП. Полученные значения заменяют текущие, отсутствующие сохраняют прежние. Изменения остаются в открытой карточке до обычной записи пользователем.

Ключ находится в игнорируемом Git файле `.env` проекта в переменной `dadata`. Сервер 1С читает этот файл по отдельно настраиваемому пути. Ключ не хранится в метаданных, константах, документации или тестовых отчетах и не передается клиенту.

Реализация через EDT-MCP, по TDD с модульными тестами YAxUnit. Целевая платформа **8.5.1.1522** — уточнение пользователя от 2026-10-13. Режим совместимости конфигурации остается **8.3.27**.

## Сценарий пользователя

1. Открыть новый или существующий элемент справочника. Поле ИНН и кнопка размещены в группе `ОсновноеЛевая` рядом с наименованием. Для группы справочника кнопка недоступна.
2. Ввести ИНН. Допустимы 10 или 12 ASCII-цифр с корректными контрольными цифрами; удалить только пробелы по краям, внутренние символы не исправлять. Пустой ИНН не запрещает обычную запись карточки.
3. Нажать кнопку. Неверный ИНН отклоняется до чтения ключа и сетевого запроса. Повторное нажатие во время запроса недоступно.
4. При успешном ответе обновить доступные для редактирования поля. Показать предупреждения о пропущенных полях, регионе и статусе организации. Не записывать объект автоматически.
5. Пользователь проверяет результат, исправляет при необходимости и записывает карточку либо закрывает без сохранения.

## Отображение данных

API возвращает `suggestions`; данные одной записи находятся в `suggestions[n].data`.

| Реквизит 1С | Источник и правило |
|---|---|
| ИНН | `data.inn`, только при совпадении с нормализованным ИНН запроса |
| Наименование | первый непустой из `data.name.short_with_opf`, `data.name.full_with_opf`, `suggestion.value` |
| Индекс | `data.address.data.postal_code` |
| Страна | `data.address.data.country` |
| Город | `city_with_type`, иначе `settlement_with_type` из адреса |
| Улица | `street_with_type` из адреса |
| Дом | непустые пары `house_type/house`, `block_type/block`, `building_type/building`, соединенные `, `; для отсутствующего типа дома использовать `д.` |
| Регион | единственная непомеченная на удаление запись существующего справочника с наименованием, равным `region_with_type` или `region` после удаления краевых пробелов и приведения регистра; объединить кандидатов и исключить дубликаты ссылок |
| Широта, Долгота | `geo_lat`, `geo_lon`: десятичная точка, округление до 6 знаков; допустимые диапазоны [-90;90], [-180;180]; ноль является действительным значением |
| Телефон | первый непустой `phones[].value`, иначе `phones[].data.source` в той же записи |
| ЭлектроннаяПочта | первый непустой `emails[].value`, иначе `emails[].data.source` в той же записи |
| ВебСайт | первый непустой `sites[].value`, иначе `sites[].data.domain` в той же записи |
| КонтактноеЛицо | `data.management.name`; если отсутствует — первый непустой `phones[].data.contact`; ФИО ИП само по себе не считать контактным лицом |

У DaData нет надежно соответствующих полей для факса, вида цен, группы, кода и дополнительной информации: сохранить их. ОГРН, КПП, ОКВЭД и прочие сведения без целевого реквизита не добавлять в свободный текст. Телефоны/почта/сайты могут отсутствовать из-за тарифа или полноты источника: это успешный частичный ответ.

Пустая строка, `null`, отсутствующий узел и пустой массив не очищают поле. Неизвестные JSON-поля игнорируются. Неверный тип необязательного поля пропускается с предупреждением. Неверная структура `suggestions`/`data`, несовпадающий ИНН или несколько подходящих записей — ошибка всего ответа, карточка не меняется.

## Решения разработчика, включенные в эту спецификацию

Чтобы сохранять полученные значения без скрытого обрезания, увеличить существующие ограничения: наименование до **150**, дом до **100**, телефон до **100**, электронную почту до **254**, сайт до **2048**, контактное лицо до **250** символов. Индекс остается **10**. ИНН — строка переменной длины **12**, необязательная для обычной записи. Для сайта используется неограниченная Строка(0) в метаданных: ограниченные строки платформы допускают до 1024 символов. При заполнении сохраняется логический предел 2048, более длинный сайт пропускается с предупреждением. Остальные типы не меняются.

Значение длиннее нового предела не обрезать: сохранить прежнее значение этого поля и показать предупреждение. Это также относится к индексу. Изменение длин — предложение разработчика, которое пользователь увидит при согласовании документов.

При отсутствии или неоднозначности региона сохранить прежнюю ссылку и предупредить; новые регионы не создавать. Координату с неверным форматом/диапазоном пропустить с предупреждением независимо от второй координаты. Статус `ACTIVE` не вызывает предупреждения; иной непустой статус показать, но разрешить заполнение. Отсутствующий статус не считать ошибкой.

## Ключ и настройка

- Новая константа `ПутьКФайлуНастроекDaData`: строка длиной 1024. Содержит абсолютный путь на машине сервера 1С к UTF-8 `.env`; не содержит ключ. Значение по умолчанию пустое, путь к текущему checkout не зашивать в исходники.
- Администратор задает путь через стандартную форму константы в «Функциях для технического специалиста». Не создавать отдельную подсистему настроек. Для текущей тестовой установки путь: `F:\1C\Projects\otus_JenkinsExample_EDT\.env`.
- Чтение пути разрешить ролям, которым доступно заполнение контрагентов; изменение/интерактивное редактирование оставить только администратору. Не добавлять привилегированный режим и не расширять существующие запреты на редактирование реквизитов.
- Файл должен быть доступен учетной записи сервера 1С. В серверной установке локальный `.env` разработчика не переносится автоматически.
- Поддержать UTF-8 BOM, LF/CRLF, пустые строки, комментарии отдельной строкой `#`, пробелы вокруг `=`, необязательный префикс `export `, некавыченный ключ либо внешние одинарные/двойные кавычки. Имя `dadata` регистрозависимо. Другие переменные игнорировать. Разделение по первому `=`; внутри значения ничего не интерполировать. Внешние кавычки должны быть парными, после них только пробелы; inline-комментарии и escape-последовательности не поддерживаются.
- Дублирующийся `dadata`, пустое значение, незакрытые кавычки и CR/LF внутри ключа — ошибка настройки. Посторонние некорректные строки без присваивания `dadata` игнорировать.
- Читать файл при каждом нажатии: изменение ключа применяется без перезапуска. Файл закрывать и при ошибке. Не читать `.env` в модульных тестах: только синтетические строки/временные файлы с вымышленным токеном.

## Вызов сервиса и ошибки

На сервере HTTPS POST к фиксированному хосту `suggestions.dadata.ru:443`, путь `/suggestions/api/4_1/rs/findById/party`. JSON UTF-8: `query` — нормализованный ИНН, `branch_type` — `MAIN`, `count` — **10**. Количество не ограничивать одной записью, иначе невозможно выявить неоднозначный ответ.

Заголовки `Content-Type: application/json`, `Accept: application/json`, `Authorization: Token <ключ>`. Для 10 цифр искать `LEGAL`, для 12 — `INDIVIDUAL`. Таймаут соединения **15 секунд**, штатная проверка TLS-сертификата, без отключения доверия и без автоматических повторов. Таймаут платформы не обещает верхнюю границу для всей операции, включая чтение файла и DNS.

HTTP 401/403 → ошибка доступа/ключа; 429 → лимит сервиса; 5xx → сервис недоступен; другие не-200 → ошибка запроса. Ответ 200 с пустым `suggestions` → не найдено; с невалидным JSON/структурой → неверный ответ. Файловая/сетевая ошибка не выводит исходный текст исключения, путь файла, заголовки, токен или полное тело ответа. Клиент получает только безопасный код и локализованное сообщение.

Коды ошибок результата: `INVALID_INN`, `SETTINGS_ERROR`, `ACCESS_DENIED`, `RATE_LIMIT`, `SERVICE_ERROR`, `HTTP_ERROR`, `NOT_FOUND`, `INVALID_RESPONSE`, `TRANSPORT_ERROR`. Транспортный код включает исключения DNS/TLS/таймаута/отправки; он не подменяет HTTP-коды полученного ответа. Для успешного результата КодОшибки пустой.

Выполнить преобразование и проверки до применения данных. Ошибка обязательных данных оставляет всю карточку без изменений; при успехе поля с предупреждениями пропускаются, остальные применяются. Для поля с запретом `Редактирование` сохранить прежнее значение и предупредить. Карточка без прав добавления/изменения не предлагает кнопку. Нельзя обходить права через преобразование формы в объект.

## Архитектура и проверяемые границы

Один новый серверный общий модуль `DaDataКонтрагенты` (без вызова с клиента и без привилегий): валидация ИНН, разбор `.env`, построение HTTP-запроса, разбор ответа, сопоставление региона, применение данных и небольшой адаптер файла/HTTP. Клиентский обработчик вызывает серверную процедуру формы. Сервер преобразует `Объект` через `РеквизитФормыВЗначение`, применяет результат и возвращает `ЗначениеВРеквизитФормы`; запись в БД отсутствует.

Модульные тесты в новом серверном общем модуле расширения `ОМ_DaDataКонтрагенты`. Чистые функции работают на JSON-строках и таблицах кандидатов. Применение проверяется на новых незаписанных объектах справочника; сравнивать значения полей, а не наличие строк в исходном коде. HTTP-запрос проверяется как реальный объект платформы с синтетическим токеном. Чтение файла проверяется на временном файле с гарантированной очисткой.

Для модульной проверки сетевых исключений `ПолучитьДанные(ИНН, Путь, Транспорт = Неопределено)` имеет одну заменяемую границу отправки HTTP. При обычном вызове третий аргумент не передается, модуль использует реальный HTTPS-адаптер. При переданном серверном объекте вызывается `Транспорт.ОтправитьЗапрос(Запрос)`, возвращающий структуру `КодHTTP, Тело` либо выбрасывающий исключение. Этот объект не принимается от клиента. Только в расширении YAXUNIT создается обработка `ОМ_DaDataТранспорт` без формы: ее незаписанный объект содержит синтетический ответ/исключение и реализует данный метод. Настоящие валидация, чтение временного файла, построение запроса, обработка исключения и разбор ответа остаются под тестом; подменяется только внешний обмен. Реальный HTTPS/TLS-адаптер проверяется отдельно интеграционным запуском; unit-тесты не доказывают доступность DaData или доверие сертификатам.

После сопоставления региона серверная форма добавляет единственную непустую ссылку в `Результат.Данные.Регион`. Если совпадение отсутствует/неоднозначно, ключ `Регион` не добавляется и формируется предупреждение; применение сохраняет прежнюю ссылку.

## Ограничения

- Не изменять платформу, режим совместимости, тестовый фреймворк или схему CI ради этой функции.
- Все чтение и запись BSL выполнять только через EDT-MCP; для точечных правок использовать `expectedHash`.
- Метаданные и формы создавать/изменять через `create_metadata` и `modify_metadata`; старые названия инструментов из правил не использовать, если сервер их не публикует.
- После записи проверять измененные объекты и форму; исходные ошибки фиксировать отдельно от новых.
- Для проверок использовать `build/ib_extend`; `build/ib` не обновлять.
- Реализация по TDD: для каждого нового поведения сначала тест, наблюдаемый RED, минимальная реализация, GREEN и рефакторинг при необходимости.
- Настоящий ключ и `.env` не включать в Git, фикстуры, скриншоты и отчеты.

## Приемка

1. Юрлицо и ИП заполняются по валидному ИНН; существующие значения заменяются только при наличии соответствующего ответа и прав.
2. Отрицательные сценарии, null/неверные типы, длинные значения, статус, регион и координаты покрыты модульными тестами без доступа к DaData.
3. Есть сохраненные RED/GREEN отчеты TDD и итоговый прогон нового модуля и всей существующей YAxUnit suite.
4. EDT не показывает новых ошибок измененных объектов относительно исходного состояния; структурная проверка формы проходит.
5. В тестовой ИБ на 8.5.1.1522 подтверждены HTTPS-заполнение, запись и повторное открытие, закрытие без записи, отсутствие утечки ключа, работа под менеджером и учет запретов на поля.
6. Отчет отделяет модульные тесты от реальной интеграции и фиксирует непроверенные сценарии. При недоступности ключа/тарифа/сети не объявлять интеграцию успешной.
