# Совместимый CI-запуск через `/C` и `/Execute`

## Цель

Обеспечить для демо-конфигурации минимальный жизненный цикл запуска, совместимый со сценарием vanessa-runner:

```text
/C "ЗапуститьОбновлениеИнформационнойБазы;ЗавершитьРаботуСистемы;"
/Execute "...\ЗакрытьПредприятие.epf"
```

При таком запуске конфигурация должна распознать команду обновления, выполнить минимальный этап после обновления конфигурации, не препятствовать запуску внешней обработки и штатно завершить сеанс средствами `ЗакрытьПредприятие.epf`.

## Границы решения

Не переносятся подсистемы БСП, хранение версии информационной базы, регистрация обработчиков миграции и формы обновления. Обычный интерактивный запуск без целевой команды не меняется.

## Решение

В модуль управляемого приложения добавляется небольшая изолированная обработка `ПараметрЗапуска`:

1. Экспортная чистая функция существующего общего модуля `СервисныеМеханизмы` делит строку по `;`, очищает элементы от пробелов и сравнивает их без учета регистра. Выделение разбора в функцию позволяет проверить его модульными тестами без запуска клиентского приложения.
2. При наличии точной команды `ЗапуститьОбновлениеИнформационнойБазы` выполняется минимальный этап обновления: сбрасываются повторно используемые значения.
3. Команда `ЗавершитьРаботуСистемы` не закрывает приложение из модуля конфигурации. Она предназначена для внешней обработки `ЗакрытьПредприятие.epf`; раннее закрытие могло бы не дать платформе выполнить `/Execute`.
4. Неизвестные элементы `/C` игнорируются, чтобы не менять существующее поведение запуска.

Обработка вызывается из `ПриНачалеРаботыСистемы` после существующей инициализации демо-приложения. Ошибка минимального этапа не скрывается: запуск завершается с ошибкой, чтобы CI не получил ложный успешный результат.

## Изменяемые объекты

- `CommonModules/СервисныеМеханизмы/Module.bsl` проекта `otusJenkinsExampleEDT` — тестируемый разбор параметра запуска.
- `Configuration/ManagedApplicationModule.bsl` проекта `otusJenkinsExampleEDT` — вызов минимального этапа обновления.
- Новый серверный тестовый общий модуль `ОМ_ПараметрыЗапускаCI` в расширении `otusJenkinsExampleEDT.YAXUNIT`.
- `tools/vrunner_ssl.json` используется как интеграционный сценарий и меняется только при обнаружении ошибки в пути или синтаксисе параметров.

Новые объекты метаданных основной конфигурации не создаются. Единственный новый объект — модуль автоматических тестов в тестовом расширении.

## Проверка

1. YAxUnit-тесты функции разбора: точное имя команды, разный регистр, окружающие пробелы, пустая строка, неизвестная команда и совпадение только по подстроке.
2. Проверка измененных модулей средствами EDT-MCP и синтаксическая проверка проекта через v8-runner.
3. Интеграционный запуск с конечным таймаутом и уникальным status-файлом через `tools/vrunner_ssl.json` на специально подготовленной для ветки базе `build/ib_extend`. Путь к базе передается запуску явно; основная база `build/ib` не изменяется.
4. Критерии успеха: YAxUnit подтверждает разбор `/C`, свежий status-файл подтверждает выполнение `/Execute`, процесс 1С завершается без зависания и команда CI возвращает успешный код.

## Не входит в задачу

- миграции данных и их версионирование;
- перенос `ОбновлениеИнформационнойБазы` и других зависимостей БСП;
- самостоятельное закрытие приложения без `/Execute`;
- поддержка произвольных команд `/C`.
